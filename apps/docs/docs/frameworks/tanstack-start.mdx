## Install

```bash
npm install @usenotra/agentside
```

## Mount the request middleware

Register a global request middleware in `src/start.ts`. It runs for every request, including server routes, so `.md` URLs work without adding routes.

```ts src/middleware/agentside.ts
import { createMiddleware } from "@tanstack/react-start";

import { twins } from "@/lib/agentside";

export const agentsideMiddleware = createMiddleware().server(async ({ request, next }) => {
  let result: Awaited<ReturnType<typeof next>> | undefined;
  const response = await twins.handle(request, async () => {
    result = await next();
    return result.response;
  });
  return result ? { ...result, response } : response;
});
```

```ts src/start.ts
import { createStart } from "@tanstack/react-start";

import { agentsideMiddleware } from "@/middleware/agentside";

export const startInstance = createStart(() => ({
  requestMiddleware: [agentsideMiddleware],
}));
```

When Agentside answers with markdown it returns the `Response` directly and the page never renders. Otherwise it calls `next()`, adds the `Link` and `Vary` headers to the page response and passes the result on.

Put `agentsideMiddleware` before middleware that redirects to a login page, and add your API prefix to `skip` so server functions are never negotiated.

```ts src/lib/agentside.ts
import { agentside } from "@usenotra/agentside";

export const twins = agentside({
  routes: {
    "/": "# Acme\n\nAcme sends invoices your customers actually pay.",
  },
  skip: ["/api", "/_serverFn"],
});
```

## Static output

Pages that TanStack Start prerenders are written as HTML at build time and served without running the middleware. Turn on prerendering in the Vite plugin and convert the client output after `vite build`.

```ts vite.config.ts
import { tanstackStart } from "@tanstack/react-start/plugin/vite";
import { defineConfig } from "vite";

export default defineConfig({
  plugins: [tanstackStart({ prerender: { enabled: true, crawlLinks: true } })],
});
```

```ts scripts/agentside.ts
import { prerenderHtml, vercelRoutes } from "@usenotra/agentside/build";

const pages = await prerenderHtml({
  dir: "dist/client",
  siteUrl: "https://acme.dev",
  llms: { title: "Acme" },
});

await Bun.write("vercel.json", JSON.stringify(vercelRoutes(pages.map((page) => page.path)), null, 2));
```

The output folder depends on your deployment target. With a Nitro preset the prerendered pages land in `.output/public` instead, so point `dir` there. When the Nitro `vercel` preset writes `.vercel/output`, convert `.vercel/output/static` and call `applyVercelBuildOutput()` instead of writing `vercel.json`, as described in [Static sites](/static-sites#framework-adapters-with-the-build-output-api).

The middleware keeps handling pages that render on demand. It serves markdown whenever `Accept` mentions `text/markdown`, the same rule the CDN uses, so both kinds of page behave alike.
